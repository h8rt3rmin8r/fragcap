# Implementation Plan: Local Steam launch-data accumulation

**Branch**: `038-launch-accumulation` | **Date**: 2026-08-14 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/038-launch-accumulation/spec.md`

## Summary

Each end user's copy of fragcap learns its own Steam games' launch executables by
reading the user's local `appcache/appinfo.vdf` and recording them in the user's
private local hint store, accumulating over repeated runs and refreshing only
what Steam changed. The launch executable then feeds the existing hint provider
(S037) with no further change. The whole capability is a local file read: no
network, no new dependency, no process handle. Three seams do the work: a new
hand-rolled binary appinfo parser and installed-library intersection in
`fragcap-steam`, a per-tier `merge_launch` plus a store-internal
`appinfo_change_number` column (the store's first v1 to v2 migration) in
`fragcap-targets`, and an accumulation orchestrator that owns the honest account
in the `fragcap` facade, driven at capture start by the CLI when a hint database
is configured.

## Technical Context

**Language/Version**: Rust, workspace edition 2021, MSRV 1.82 (must stay green).

**Primary Dependencies**: none new. The binary parser is arithmetic over a byte
slice (the S03/S06/S031 hand-roll precedent). Existing crates only: `rusqlite`
(store, already a `fragcap-targets` dep), the standard library.

**Storage**: the existing embedded SQLite hint store (`fragcap-targets`). This
slice adds one nullable column via a schema-version migration (v1 to v2) and
writes only launch rows plus that column.

**Testing**: `cargo test --workspace --locked`. Offline throughout: the appinfo
parser is tested against synthetically generated bytes; the orchestrator is tested
in the facade against a fixture Steam-root tree (text appmanifests plus a
synthetic binary `appinfo.vdf`) and an in-memory store. No Steam, no network, no
capture driver.

**Target Platform**: Windows for the live path (Steam root via registry); the
parser, the library intersection given a root, the merge, and the orchestrator
are all portable and build and test on the neutral non-Windows target (P-2).

**Project Type**: Rust workspace (library crates plus a CLI facade).

**Performance Goals**: repeat runs do near-zero work (every installed app skipped
by change-number). A first run parses the local appinfo file once (tens of MB
read sequentially) and does one SQLite transaction per written app. Progress is
surfaced so a first run reads as working, not hung (FR-010).

**Constraints**: no network and no `net` feature (FR-012); no process handle,
file read only (FR-013, P-1); no new dependency (FR-014); launch entries stored
verbatim (FR-005, P-9); every considered app in exactly one counted outcome
(FR-007, P-4).

**Scale/Scope**: the considered set is the installed library (typically tens to a
few hundred apps), not the whole appinfo cache (thousands).

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **P-1 Passive Observation Only**: Satisfied. The only new I/O is reading a file
  Steam already wrote (`appinfo.vdf`) plus the existing library enumeration. No
  process handle of any kind (the `OpenProcess`/`ReadProcessMemory` lint stays
  clean); no capture driver; no transmit. FR-013 and SC-006 make this testable.
- **P-2 Core Stays Platform-Neutral**: Satisfied. `fragcap-core` is untouched.
  The parser and orchestrator carry no platform dependency; only Steam-root
  discovery (pre-existing, Windows-only) is platform-specific, and the offline
  path takes a root as a value. Dependencies flow concrete to abstract:
  `fragcap-steam` and `fragcap-targets` stay siblings that do not depend on each
  other; the orchestrator lives in the facade, the only crate that may depend on
  both. `cargo xtask deps` proves the graph is unchanged.
- **P-3 Capture And Attribution Stay Separate**: Satisfied. No capture or
  attribution code is added or merged; accumulation runs before capture arms and
  writes only to the hint store.
- **P-4 No Silent Loss**: Satisfied. Every considered app lands in exactly one of
  written, skipped-as-current, failed-to-parse, or yielded-nothing, and the
  counts reconcile to the considered count (FR-007). A single unparseable app is
  counted and skipped, not fatal (FR-008), using the appinfo section-size framing
  to resync.
- **P-5 Compatibility Outranks Richness**: Not engaged. No output-format change.
- **P-6 Glossary First**: New terms (application-info cache, launch-data
  accumulation, accumulation account, change-number staleness) get glossary
  entries in this change.
- **P-7 Wrappers Stay Thin**: Satisfied and reinforced. This adds the capability
  in Rust rather than scraping a `steamcmd` subprocess (a rejected alternative,
  see research.md); no wrapper parses anything.
- **P-8 House Standards Apply**: Satisfied. SPDX headers, UTF-8 no BOM, LF, no
  em/en dashes; `cargo fmt`, `clippy -D warnings`, and the repository linter gate.
- **P-9 The Instrument Does Not Lie**: Satisfied and central. Launch entries are
  stored exactly as the cache records them, with no reduction, reordering,
  normalization, or filtering (FR-005). Fields with no reliable source
  (`launcher_mediated`, `token_required`) are left untouched rather than guessed
  (FR-015, FR-015a). The account is surfaced, not silently truncated.

**Licensing**: no new dependency, so no license surface changes; `Cargo.lock` is
unchanged (SC-007). No npcap interaction.

**Result**: PASS. No violations; Complexity Tracking is empty.

**Structure Decision**: Three seams respecting the sibling rule. The Steam
file-format work (binary parser, installed-library intersection) lives in
`fragcap-steam`, which already owns Steam metadata reading and is P-1 clean. The
per-tier `merge_launch` and the store migration live in `fragcap-targets`, the
column owner, mirroring the existing `merge_catalog`/`merge_engine`. The
orchestration that needs both siblings lives in the `fragcap` facade behind the
`targets` feature, tested end to end there (the S07/S08 facade-test precedent).
The CLI's `run.rs` invokes it and prints progress. This keeps `cargo xtask deps`
green with the existing edge set unchanged.
