<Callout title="Why it matters here">
Every command that captures needs the **npcap** driver installed in
WinPcap-compatible mode. Run `fragcap doctor` first; it reports the driver's
presence without capturing anything.
</Callout>

fragcap has one binary and a small set of commands. This page lists what each one
does and the flags it accepts. The binary's own `--help` is authoritative and is
generated from the same definitions; this page is the readable version.

## Global options

These apply to every command:

| Flag | Effect |
| --- | --- |
| `--quiet` | Suppress progress; keep warnings and errors. |
| `--silent` | Suppress everything except errors. |
| `--json` | Emit newline-delimited structured events on standard error. |

## `run`

Capture a game using a profile. This is the primary command.

```text
fragcap run --profile eso --out capture.fcapng
```

| Flag | Meaning |
| --- | --- |
| `-p, --profile <REF>` | The profile to capture with: a path, a name, or a game id. Required. |
| `-o, --out <PATH>` | The output capture file (pcapng). Shorthand for a file sink. |
| `--mode <MODE>` | Capture mode: `file`, `stream`, or `ring`. Defaults to the profile's, or `file`. |
| `--sink <SPEC>` | An output sink, repeatable: `file:PATH`, `jsonl:PATH`, `pipe:NAME`, or `tcp://HOST:PORT`. |
| `-d, --duration <DUR>` | The capture duration bound, measured from arm. |
| `--wait <DUR>` | How long to wait for the target before giving up (the acquisition timeout). |
| `--max-packets <N>` | Stop after this many captured packets. |
| `--max-bytes <SIZE>` | Stop after this many captured bytes (integer plus `b`/`kb`/`mb`/`gb`). |
| `--roles <A,B>` | The roles to capture, comma-separated. Scopes which stages trigger (enforced). |
| `--direction <DIR>` | The flow direction to scope to: `in`, `out`, or `both`. Recorded but not yet enforced (see below). |
| `-i, --interface <NAME>` | A capture interface, repeatable. |
| `--loopback` | Include the loopback adapter. |
| `--no-payload` | Write metadata only, no packet payloads. |
| `--ring <WINDOW>` | The ring window, for `--mode ring` (a duration or a size). |
| `--launch` | Launch the game through its platform before capturing. |

Durations accept the same grammar throughout: an integer and a unit, such as
`30s`, `5m`, or `2h`. See [capture modes](/docs/guides/capture-modes) for what
`--mode` and `--ring` do.

<Callout title="Directional filtering is not yet enforced">
`--direction in` or `--direction out` is recorded on the effective configuration
and reported, and fragcap warns that directional output filtering is deferred: a
non-default direction does not currently scope the captured packets, so the
output still contains both directions. `--roles` scoping, by contrast, is
enforced.
</Callout>

## `tap`

Capture a running process ad hoc, without an authored profile. Names the process
by image name rather than resolving a profile.

```text
fragcap tap --process discord.exe --out capture.fcapng
```

| Flag | Meaning |
| --- | --- |
| `-p, --process <NAME>` | The image name of the process to capture. Required. |
| `-d, --duration <DUR>` | The capture duration bound. |
| `-o, --out <PATH>` | The output capture file (pcapng). |
| `--sink <SPEC>` | An output sink, repeatable. |
| `--no-payload` | Write metadata only, no packet payloads. |

## `profile`

Manage and validate profiles. A `--profile-dir <PATH>` may be repeated to add
directories to the search.

- `fragcap profile validate <REF>` reports every diagnostic in one pass. A
  profile with four mistakes reports four; see [the schema](/docs/reference/profile-schema).
- `fragcap profile list` lists the bundled and user profiles with counts.
- `fragcap profile show <REF>` shows how a reference resolves and which source
  supplied it.

## `steam`

Enumerate titles and scaffold profiles from a Steam installation.

- `fragcap steam profile <APP_ID>` reads Steam's local metadata for an installed
  title and prints a validating profile skeleton to standard output. It captures
  nothing and touches no process; it is a starting point you then edit.

## `doctor`

Report environment readiness: whether the capture driver is present and whether
fragcap can enumerate interfaces. It captures nothing.

```text
fragcap doctor
```

## `extcap`

Analyzer integration. Wireshark and compatible analyzers invoke `fragcap` as an
extcap capture source; you do not normally run the protocol form by hand. It
presents one `fragcap` interface whose options (`--profile`, `--roles`,
`--direction`, `--loopback`) mirror `run`, so the analyzer's capture dialog and
the command line select capture identically.

### `extcap install` / `extcap uninstall`

Register or unregister fragcap as a Wireshark extcap source, so Wireshark lists
it in its capture interfaces.

```text
fragcap extcap install            # register for the current user (the default; idempotent)
fragcap extcap uninstall          # unregister (idempotent; a no-op if not registered)
fragcap extcap install --system   # register machine-wide, for every user
fragcap extcap install --dir DIR  # register into an explicit directory
```

The scope selectors `--user`, `--system`, and `--dir` are mutually exclusive; with
none given, the default is the current user. `--user`/`--system` register into the
per-user and machine-wide Wireshark extcap directories `doctor` probes, and `--dir`
is an explicit override (the same directory selected by a scope, named literally).
The flags apply to `uninstall` as well.

**The default is per user.** It copies the running fragcap binary into your own
Wireshark extcap directory and needs no elevation. Installing fragcap for the whole
machine does not register it for everyone: on a shared computer, **each user who
wants the Wireshark integration runs `fragcap extcap install` once.** If Wireshark
does not show fragcap as a capture source, run `fragcap doctor`, which reports
whether the integration is registered for you and prints the exact command to fix
it.

To register for every user of the machine, an administrator runs the machine-wide
form (writing into Wireshark's system extcap directory needs the privilege to write
there):

```text
fragcap extcap install --system
```

`--system` resolves the system Wireshark extcap directory for you; to target a
non-standard location, name it explicitly instead, for example
`fragcap extcap install --dir "C:\Program Files\Wireshark\extcap"`.

### From the installer

The Windows installer (`.msi`) can register the integration for you. Its optional
Wireshark integration step offers two independent, opt-out choices, both off by
default so nothing is registered unless you ask:

- **For the current user** runs the per-user registration above as the installing
  account, so it lands in your own Wireshark extcap directory.
- **For all users on this machine** registers into Wireshark's system extcap
  directory when Wireshark is detected. It is ignored if Wireshark is not found.

A failed registration never fails the install, and leaving both unchecked
registers nothing; you can always run `fragcap extcap install` later. Both choices
are also public installer properties (`REGISTEREXTCAP_USER`,
`REGISTEREXTCAP_MACHINE`), so an administrator can set them for a silent install.

## `replay`

Play a capture file back. Not yet implemented; the command parses and reports that
it is unavailable rather than the parser rejecting it.
