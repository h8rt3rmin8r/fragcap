## Selected TCP

A positive controlled external TCP row names the original selected tuple, exact final-client generation, route receipt, client-visible handshake, two-way application byte equality, and terminal reason. It reports independent active sentinel continuity and route packet loss. An upstream CONNECT or WinDivertSend success without observed client delivery is non-positive.

## Direct calibration

For equal exact route and client evidence, original-present and original-absent cases yield the same route verdict and distinct passive packet availability. A passive history gap remains visible but cannot revoke independent exact route proof. Conflicting owner, reused generation, incomplete route proof, refusal, and no-payload cases never produce a positive stored fact or ordinary admission. Compatibility and terminal reasons are checked against the same decision.

## Native report

The report is a bounded, read-only projection. Each selected flow exposes route, proxy, packet, calibration, and terminal availability without private endpoint or secret receipt in the shareable output. A missing route stream, writer gap, or crash prefix cannot become a complete source. Human and JSON summaries agree on the decision and incomplete status. Export refuses source aliasing and leaves native bytes untouched.

## Qualification provenance

Each required row names its executor and actual result. Driver-free fixtures, signed-driver probes, certified package layouts, and a true installed default journey are distinct evidence classes. A hosted package check cannot establish local default native storage. Remote controlled-peer tests record port availability before and after and create no persistent cloudbase file or service.
