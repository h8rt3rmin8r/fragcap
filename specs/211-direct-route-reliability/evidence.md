## Source and local checks

The first PR review on commit `9c047e7` identified three valid defects: pending helpers were omitted from flow capacity, a fragmented SOCKS reply could outlast the absolute helper deadline, and a timed-out physical test could leave descendants running. Commit `37d01af` counts pending flows before issuing a receipt, bounds each socket read and write by the remaining deadline, and assigns the gated physical test worker to a kill-on-close Windows Job Object before it can start descendants. A driver-free job probe verified descendant termination. The fragmented-reply test sends one byte every 30 ms against a 120 ms budget and rejects late completion. The full local `cargo xtask ci` gate passed at `37d01af`, and its hosted Windows native integration and CodeQL checks passed.

The second and final Codex review of `37d01af` found that a helper registered before receipt consumption could falsely report a consumed receipt, and that pending first-packet loss after owner change or shutdown lacked a per-flow disposition event. The subsequent source change records actual ledger consumption and emits the lost disposition with aggregate loss. Focused native reconciliation tests passed. The complete local gate and hosted checks for that later source change remain pending.
