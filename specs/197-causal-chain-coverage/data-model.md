# Data Model: Causal Launch-Chain Coverage

## Managed process generation

One session-created instance has a PID, creation instant, canonical executable path, account, Windows session, parent generation, root launch receipt, causal depth, start and exit instants, and optional retained query/synchronize receipt. The key is PID plus creation instant. A path, image name, or PID alone is never a membership or process-control key. Missing proof produces incomplete identity, not a guessed owner.

## Causal membership interval

Each proven generation has a start-inclusive and exit-exclusive packet eligibility interval. It is published immutably to packet admission, loopback orientation, endpoint narrowing, and shutdown inventory. A reused PID creates a separate interval.

## Packet evidence decision

One observed packet has its original timestamp, interface and flow identity, optional attributed generation, and an outcome of retained, pending, waiting, out-of-window, out-of-scope, unresolved, or capacity/source loss. At most one writer-held head waits for proof while later packets remain in the existing bounded fan-in buffer; a managed-session byte ceiling also applies. Each non-retained outcome contributes one named count and, where a flow exists, a matching omission cause.

## Coverage windows

Managed launch begins full-chain packet eligibility. Client observation retains its separately authorized duration and terminal reason. Packet coverage ends at verified route release or its finite deadline, unless a named source, storage, packet-limit, or byte-limit failure ends earlier. Metadata names every gap between these intervals.

## Inspection policy identity

Requested scope remains `auto`, `game`, or `launch-chain`; effective application scope resolves before effects. Managed packet scope is full causal chain regardless of application choice. Middleware handling, route strategy, family, target version, and new policy identity remain exact compatibility dimensions. Historical rows are immutable and readable, but mismatched rows do not qualify.

## Route-owner release

The inventory contains exact live generations and incomplete plausible descendants. Proven owners enter the authorized graceful/force sequence, followed by exit verification. Incomplete instances receive no control. Result records actions and proof failures, release times, listener and route state, and current Doctor obligations independently of historical session outcome.
