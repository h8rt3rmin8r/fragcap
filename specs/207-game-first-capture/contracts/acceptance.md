# Acceptance Contract: Game-first Deep Capture

| Case | Required observation |
| --- | --- |
| First ordinary capture, no prior facts | One pre-effect authorization leads to a bounded attempt and current-session facts; no calibration prerequisite. |
| Stale or negative historical row | Row remains readable, does not veto admission or alter the selected route. |
| Default zero-, one-, and multi-intermediary chain | No Fragcap launcher proxy assignments; exact final-game direct route; no intermediary payload in retained packet or application evidence. |
| Ambiguous final owner | No proxy route or retained payload promoted to game evidence; uncertainty and accounting remain explicit. |
| Explicit advanced SOCKS-only launch chain | Authorization names SOCKS assignments and full-chain scope; no HTTP proxy URL assignment; applied effects match; authenticated fixture transfers in both directions. |
| Plan/effect mismatch | Refusal occurs before any proxy, trust, driver, capture, or launch effect. |
| HTTP CONNECT response then immediate client close | Pre-TLS client handoff is named; no invented trust, origin, or TLS failure. |
| Empty, delayed, partial, EOF, and read-error SOCKS prefixes | Unknown provenance; no positive plaintext or decryption fact; forwarded bytes and loss accounting unchanged. |
| Positive TLS or cleartext evidence | Classification states only the stage actually observed; encrypted shape is distinct from completed decryption. |
| Unrelated sentinel during direct route | It continues through the bounded pass-through, with zero unrelated payload retained and accounted observations. |

The full repository gate and applicable controlled Windows matrix are the completion evidence. A private installed game run is separately reported if performed, and is not inferred from these fixtures.
