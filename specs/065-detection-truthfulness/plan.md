# Implementation Plan: Detection truthfulness and the column split

**Branch**: `065-detection-truthfulness` | **Date**: 2026-08-20 |
**Spec**: [spec.md](./spec.md)

**Input**: Feature specification from
`specs/065-detection-truthfulness/spec.md`

**Closes**: #169, #168, #174

## Summary

Make the technology evidence say what was actually observed, then split the one
column that renders it into two columns with one job each.

Three changes, in the order that makes each one demonstrable:

1. Drop the two Steamworks SDK signature rows that produce a false "Steam DRM"
   on 28 of 32 rows, and replace them with a real one: a `binary-marker`
   signature matching a `.bind` PE section, which is the measured discriminator
   for the Steam DRM wrapper. The binary-marker kind already exists in the
   vocabulary and is inert; this makes one pattern form of it matchable and
   leaves the three byte-sequence rows explicitly inert and counted.
2. Add Ren'Py and GameMaker engine signatures, and settle the dual-detector
   question with a directed subset invariant enforced by a test in the ordinary
   gate.
3. Split `KNOWN` into `ENGINE` and `SENSITIVITIES`, partitioned on the
   signature category that the data already carries; retire the two readiness
   fallback sentences that were only in that column because it was the only
   free one; and plumb a coverage field so that "scanned clean", "never
   scanned", and "scan incomplete" are three visibly different things instead
   of three blanks.

## Technical Context

**Language/Version**: Rust, workspace MSRV 1.82, pinned toolchain in
`rust-toolchain.toml`

**Primary Dependencies**: none added. The PE section reader is arithmetic over
a byte slice beside the existing version-resource reader; the signature matcher
already uses `regex`; the store already uses `rusqlite`.

**Storage**: `local.db` and `catalog.db` through
`fragcap-targets::store::Store`. Schema version moves 6 to 7 for one additive
nullable column.

**Testing**: `cargo test --workspace --locked`, plus the repository checks in
`cargo xtask ci`. Every new behavior is testable with no game, no capture
driver, and no platform install: the PE fixtures are generated bytes and the
engine trees are temporary directories.

**Target Platform**: Windows for the shipped tool; every test in this slice is
platform-neutral and runs on any target the workspace builds for.

**Project Type**: Rust workspace, eight crates, CLI plus libraries.

**Performance Goals**: a section-table read costs one bounded 64 KiB prefix read
per candidate executable, capped at 64 candidates per install directory, so
detection over a 100 GB install stays in the low megabytes of I/O.

**Constraints**: passive observation only (P-1); no dependency added; no silent
loss (P-4); the 80 column terminal budget for the widened listing.

**Scale/Scope**: 32 registered targets on the operator's machine, 23 signature
rows in the shipped seed rising to 26.

### Contracts

This slice touches three contracts that outlive it.

**The signature seed row grammar** (`crates/fragcap-targets/assets/signatures.json`,
Appendix B of the master specification). A row is
`{category, kind, pattern, product, confidence}`. This slice adds one pattern
grammar within the existing `binary-marker` kind:

```text
pattern := "section:" <glob>     # matchable: a PE section name
         | <anything else>       # inert: a byte-sequence form, not implemented
```

An inert row is counted, never dropped, and never treated as malformed. An
empty glob after `section:` is a malformed row and is skipped and counted.

**The target-entry export object** (`targets export` / `targets import`) gains
one optional key:

```text
"detection_scan": "complete" | "incomplete"
```

Emitted only when a scan is recorded. Absent means no scan is recorded. An
out-of-set value is rejected at import, applying nothing, which is the existing
all-or-nothing rule.

**The listing table**. The `KNOWN` column is replaced by `ENGINE` and
`SENSITIVITIES`. This is a user-visible output change and belongs in the
release notes.

## Decision log

Decisions taken under the autopilot policy during this slice. The two marked
*architecture* also get a `changelog.d/*.decisions.md` fragment.

| # | Decision | Why | Alternative rejected |
| --- | --- | --- | --- |
| D-1 | Drop the two Steamworks SDK signature rows rather than recategorize them | A fourth category needs a fourth rendering bucket in the slice whose subject is category conflation, and a row that fires on nearly every Steam title carries no information | A `platform-sdk` category with product `Steamworks SDK`; keeping the rows and adding `.bind` alongside |
| D-2 (*architecture*) | Keep the two engine detectors separate, bound by a directed subset invariant enforced by a test | They answer different questions, and the signature schema carries no per-engine client-selection rule; the invariant catches the failure that actually hurts | #168 option (a), folding the launch rules into the signature table |
| D-3 (*architecture*) | Carry the coverage state as a typed nullable column, schema 6 to 7 | The export key set is a reviewed contract by design and an out-of-set value must be rejected; #174 calls this a P-4 concern | Storing it in the free-form `provenance` blob; distinguishing only two states via an empty `evidence` array |
| D-4 | Retire the two readiness fallback sentences rather than move them into the readiness column | Each is a relabeling of a readiness state the column already prints, so moving them prints the same fact twice and costs 16 of an 80 column budget | #174's own sketch, `ready, no online mode recorded` |
| D-5 | No truncation and no wrapping; columns size to content, sensitivities last and free-running, and the budget is stated over the columns the tool controls (53 of 80, leaving 27 for a handle) | Truncation is the silent loss P-4 forbids, wrapping breaks the alignment the split exists to provide, and the handle is operator data of unbounded width so a budget stated over the whole row would be a claim about someone else's naming | Ellipsis truncation of the sensitivities column; wrapping a long row; claiming an 80 column fit the operator's own machine does not meet |
| D-6 | Depth bound 4 is definitional for the candidate set; only the count cap is counted as loss | A redistributable installer at depth 6 is not a launch-target candidate, so counting it would make the loss number noise rather than signal | Counting every excluded `.exe`; no depth bound at all |
| D-7 | Replace `SignatureKind::is_implemented(&self)` with `Signature::is_matchable(&self)` | Matchability now depends on the pattern as well as the kind, so it is a property of the row | Keeping `is_implemented` and adding a second gate beside it, which would leave two places to forget |

## Verification

`cargo xtask ci`, run in the foreground and watched to completion, is the gate.
It runs format, clippy with warnings denied, the workspace test suite, the
repository lint, the dependency-direction check, and the license check. The
directed subset invariant of D-2 rides in the workspace test suite, so it is in
the ordinary gate rather than beside it.

Beyond the gate, the slice is verified against the operator's machine per SC-001
and SC-002, and against the rendered output rather than the source that produces
it, per the standing lesson that a fix must be checked as an artifact.

## Risks

| Risk | Mitigation |
| --- | --- |
| The `.bind` claim is measured on seven titles, not proven in general | Recorded as an assumption with its sample; a false negative is an absent label, which is the safe direction, and a false positive would need a non-Steam product to use the same section name |
| The operator's listing is 100 columns wide and does not fit an 80 column terminal | Declared behavior under D-5, covered by a test that asserts the overflow is real and nothing is clipped. The cause is a 47 character handle, which is target identity, addressed by #166 and #173 in slice S066 |
| Removing `known_summary` breaks a caller outside the crates surveyed | The workspace build finds every caller; removal rather than deprecation is deliberate so no caller keeps the flattened form |
| The schema bump means an older build cannot open a store this build wrote | Already the project's stated behavior: a newer version is an error, not a silent operation on an incompatible layout. Five prior migrations set this precedent |
| The section scan bounds are wrong for a layout nobody has measured | The bounds are exposed as named constants with the measurement that set them, and a truncated scan reports incomplete coverage rather than a clean scan, so the failure is visible |
