# Contract: native documentation registry version 2

## Registry closure

The registry declares exactly schema version 2, the published baseline, current-source boundary, thirteen ordered topics, example authorities, and the five-issue completion boundary. Unknown or missing fields fail. Topic, section, example, test, feature, source-boundary, and issue identities are unique.

## Page and section authority

Every topic names one confined current MDX page and a non-empty ordered section list. A page beneath historical changelog or glossary content cannot serve as current product authority. Every section must be an exact authored level-two or level-three heading outside fenced code. A missing, duplicated, or out-of-order required section fails with the topic and section identity.

## Executable authority

Every topic has at least one exact non-ignored Cargo-discoverable test under explicit features. The existing shared discovery mechanism remains authoritative for test ownership and feature applicability. A source comment, helper function, ignored test, impossible configuration, absent file, unsupported nested harness, malformed feature list, or missing function fails.

## Command corpus

One command-corpus authority binds current README and every nonhistorical site MDX file to the production command parser test. Verification discovers fragcap invocations in all fenced blocks except Mermaid, joins supported shell continuations, removes unquoted comments, normalizes documented placeholders, and calls command parsing without dispatch. The default and network-capable trees both run. Retired Deep Capture `--trust-ca` and `--yes` inputs fail current guidance.

## Artifact examples

Committed manifest version-one and version-two specimens are read by the versioned manifest reader. Packet pcapng and JSON Lines goldens are regenerated only through their owned fixture path and compared by exact writer tests. The complete native bundle, application stream, HAR, process trace, proxy and cleanup streams, correlation projection, and public API example are owned by exact controlled executable contracts when no safe standalone specimen exists. JSON syntax alone is never sufficient authority.

## Status truth

Current pages may state that S154 through S156 are merged current-source verification work. They must not call those changes part of published v0.10.1 unless the release identity actually contains them. They must preserve Deep Capture as functional but incomplete and keep #333, #413, #331, #334, and #278 separate. Review readiness, green CI, bot review, hosted replay, and package certification never become independent security acceptance.

## Scope exclusions

This contract changes no runtime, protocol, route, trust, consent, cleanup, package, version, release, registry policy, or API behavior. It authorizes no installed product execution, game launch, live capture, trust-store mutation, or independent-review claim.
