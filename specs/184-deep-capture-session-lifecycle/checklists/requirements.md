## Issue and scope traceability

- [x] CHK001 Do the scenarios and requirements cover every acceptance item in #526 and #527 without claiming #528 or #529 complete?
- [x] CHK002 Are owner release, observation timing, and the interim trust obligation described as distinct outcomes?
- [x] CHK003 Are out-of-scope real-title, publication, persistent CA, and unrelated-process control boundaries explicit?

## Ownership and cleanup

- [x] CHK004 Does the spec distinguish proven owner receipts from same-named unproven events without granting the latter control rights?
- [x] CHK005 Are late owners, helpers, failed control, failed exit verification, and unresolved plausible owners covered?
- [x] CHK006 Are route, target-route, proxy, trust, Doctor, and terminal claims tied to observed live state rather than only local resource teardown?

## Timing and evidence

- [x] CHK007 Are calibration and ordinary duration rules distinct and is the existing ordinary finite ceiling explicit?
- [x] CHK008 Are invalid or over-limit values required to refuse before effects rather than silently clamp?
- [x] CHK009 Does the spec require plan, actual arm-to-stop, Capture span, and terminal consistency for a run longer than one minute?
- [x] CHK010 Are the controlled Windows and installed-path evidence cases specified without private title identity or workstation GUI reliance?

## Quality gates

- [x] CHK011 Does each measurable outcome have a direct repository-controlled test or review gate?
- [x] CHK012 Does the handoff distinguish source qualification, installed-path evidence, exact-head CI, external reviews, and later owner merge?
