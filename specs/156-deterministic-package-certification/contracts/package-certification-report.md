# Package Certification Report Contract

Package report schema 4 records deterministic controlled reachability separately from firewall, process, socket-diagnostic and cleanup evidence.

## Positive authority

Each `portable` and `installed` row requires exactly one structured native proxy-start event and exactly one terminal reached-client calibration event from the same nonempty session. The two rows must carry distinct SHA-256 session identities, so one execution cannot certify both surfaces. Startup must bind an exact IPv4 or IPv6 loopback address and a positive port. The terminal event must bind reachability, `direct-exe-warm`, child-environment routing, routing protocol, complete stage and reached-client status.

## Preserved negative authority

The exact packaged executable remains under an installed outbound firewall block for Internet and LocalSubnet destinations. Process observation covers the root and complete descendant set. Any unexpected executable or sampled non-loopback address fails. Observation must complete with at least one sample and one product process. Cleanup must reconcile the firewall rule and all existing package lifecycle effects.

## Diagnostic socket evidence

Endpoint count and exact-loopback sampling are observations, not success prerequisites. Zero sampled endpoints and `loopback_socket_observed=false` are valid when deterministic structured authority is complete. A nonzero non-loopback count is always invalid.

## Diagnostics

The Rust event validator and PowerShell host observer report failed predicates from closed ordered vocabularies. The wrapper transports the Rust-owned predicate diagnostics without replacing them, and emits at most sixteen identifiers and at most 1 KiB, without raw event data, paths, addresses, process identifiers, payloads or credentials. The validator rejects a terminal reached-client event that does not follow proxy startup.

## Compatibility

The validator accepts schema 2 and schema 3 under their historical rules for retained-report inspection. Only schema 4 is emitted. Unknown versions, missing fields, unknown fields and mixed schemas fail.

## Hosted acceptance

The `Published review candidate` and `Windows package certification` workflows must both pass on the final pull-request head without retry. Local validation does not execute the installed product.
