# S182 data model

## Target and proposal

An anchored target retains stable ID, handle, platform anchor, authored roles, root, and historical compatibility. A proposal carries old/new roots, exact anchor, executable/role validation, discovery evidence, and store revision. States: unavailable, ambiguous, unchanged, changed executable, unique supported. Only the last permits exact confirmation and root update. Historical measurements remain stored but applicability is re-evaluated.

## Packet omission

A flow retains timestamped packet observations and bounded omission intervals. An interval has first/last observed time, cause (scope withheld, history capacity, unknown), and count. Adjacent same-cause intervals coalesce; bound exhaustion becomes a conservative unknown span. Global acquisition loss remains unlocalized. Positive correlation requires exact ownership in the eligible connection interval and no unresolved overlapping omission.

## Process and session

A controllable owner has an exact process object, creation time, canonical image, account, session, receipt, and proven ancestry. A helper is an observed descendant without control authority. Owner transitions are proven live, grace requested, force requested, exit verified. Helper exit must be observed before route release. Observation cutoff, stop, drain, runtime cleanup, application trailer, manifest, and terminal each retain separate provenance. Metrics are observed values or unavailable with reason; later cleanup counts cannot alter the calibration cutoff.

## Qualification

The package contract names ordinary/delayed imports, exact MSI/ZIP hashes, startup behavior, lifecycle effects, and user-state sentinels. Physical reference names published product version, revision, staged hash, matrix digest, date, authority, and seven row outcomes. Unreleased candidate qualification is distinct.
