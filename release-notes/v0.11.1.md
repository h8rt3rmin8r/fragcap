# Highlights

v0.11.1 brings the latest direct-route fixes and clearer evidence for a fresh Windows test run.

- Direct TCP replies now use the resolved inbound interface, and calibration requires confirmed two-way transfer before recording reachability.
- Managed direct launches can use their exact process receipt when the first packet arrives before the process watcher event; known unrelated sockets pass through promptly.
- The protected route trace and shareable debug report distinguish selected transfer, packet evidence gaps, process ownership, and cleanup without exposing private endpoints.
- Managed packet correlation records bounded, flow-local omission reasons. SOCKS5 classification and incomplete application streams are reported accurately.
- The release includes the rustix advisory update and controlled external IPv4 and IPv6 route qualification.

The corrected calibration and correlation paths still need a fresh installed-package test. An original-present Npcap ordering has not been observed.

For the complete change history, implementation details, and issue references, see the [full v0.11.1 changelog](https://github.com/h8rt3rmin8r/fragcap/blob/v0.11.1/CHANGELOG.md).
