# Remediate an existing Workflowy workspace

Use this procedure when asked to migrate records from an earlier skill version. Scope the repair to the authorized projects or collections. Review the [current layout](workspace-layout.md), [record contract](record-format.md), and [MCP methods](workflowy-mcp.md).

1. Read the destination and existing direct records. Inventory authored bullets, legacy wrappers, nested dated entries, slice codes, date metadata, distinct evidence, links, and comment threads. Keep node IDs and order in the work inventory. Treat backlink excerpts as generated navigation and confirm apparent blank wrappers before editing them.
2. Match by subject and evidence, then choose one canonical record. Move or retitle in place to preserve IDs. Use verified source timestamps over display dates or inferred times. Extract the short description into `title`, split tags under `tags`, and put prose under `details`. Lift independently dated entries to direct siblings under `notes`, keep their relationship through links, and sort oldest first. A date mentioned in a finding or source does not turn it into another note.
3. Use the same nesting for existing inline metadata. Set the Workflowy block format to `bullets` for each structured field and value. Inside `details`, preserve meaningful formatting. Move inline hashtags from titles and fields into one `tags` field with one native hashtag per bullet. Verify the tags there before stripping them from the source. For project-level tags, use `info > tags`. Under `info`, retain only `tags`, `links`, and `details` as direct children. Move all other fields under `details`, preserving node IDs and values. Standardize reusable keys in place with lowercase letters and underscores. Convert Remote Data `URL` fields to `links`. Remove imported `Source ID` fields and retain any distinct verified links they contained. Split multi-link rows into individual bullets and preserve the underlying targets and exact source locators. Preserve prose containing colons and ordinary source dates. Remove generated timeline rows only after the authoritative date and scope tags survive. Keep one formal slice per code/title, normalize its fields, and link dated slice narrative to its note.
4. Recover substantive notes from comments and drafts into normal bullets with author, source date, and evidence when accessible. Keep a stable destination for each recovered record. Compare the full content, children, and link targets with the source. Only then delete the original comment or draft using an operation verified to work for that item. Preserve unrelated replies and leave inaccessible drafts or unsupported deletions in place for operator follow-up. Never use comments or drafts as record storage. [Workflowy comments and drafts](https://community.workflowy.com/t/fractal-comments/1681)
5. For duplicate bullets, retain meaningful evidence, update in-scope pointers to the canonical bullet, and remove only copies whose retained content and destination have been verified. Re-read before deleting wrappers or retrying uncertain operations. Keep unresolved dates or links intact and report their locations.
6. To flatten an older **STANDARDS** outline, move each standard directly under the existing root and sort by title. Apply the topic tags in the [workspace layout](workspace-layout.md#standards). Preserve record IDs, whether each directive is a `rule` or a `default`, and any scope and links. Remove old category headings after verifying they are empty and resolving any inbound links.
7. Re-read the final title, parent, date precision, order, tags, links, and source coverage after each batch. A rerun should make zero duplicates. Replace only the earlier Workflowy opt-in block in affected project instructions when requested. Report remaining exceptions by destination so the operator can resolve them.
