# Evidence and Lifecycle Requirements Checklist: S182

**Purpose**: Check whether the specification defines enough truth and authority to review calibration, correlation, and managed shutdown design.
**Feature**: [S182 specification](../spec.md)

## Correlation and Timing Requirements

- [x] Does the specification separate the finite launch, observation, drain, shutdown, and cleanup deadlines?
- [x] Does it define what normal completion and genuine overrun mean for the real Capture adapter?
- [x] Does it require omission cause and interval information before a positive final-client decision?
- [x] Does it state when withheld history may be irrelevant to a later exact connection?
- [x] Does it preserve refusal for overlapping missing data, conflicting ownership, and tuple reuse?
- [x] Does it keep routing and TLS as separately authorized, independently evidenced facts?
- [x] Does it prohibit a successful compatibility claim from a merely written bundle or authenticated proxy connection?

## Process and Artifact Authority Requirements

- [x] Does the specification limit process control to exact session-created proven owners?
- [x] Does it distinguish a helper observed for release evidence from an owner eligible for a control request?
- [x] Does it require verified exit before route release is reported as complete?
- [x] Does it preserve visible partial cleanup when exact identity or exit cannot be proved?
- [x] Does it distinguish unavailable metrics from observed zero after a proxy stop timeout?
- [x] Does it require terminal, application, process, manifest, and cleanup populations to reconcile without erasing failures?
- [x] Does it identify privacy and published-byte field-test boundaries without weakening controlled qualification?

## Notes

- These are requirements-writing checks. Implementation tests and exact process-right audits belong to the plan and tasks.
