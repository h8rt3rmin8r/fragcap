# Implementation Plan: Hint database resolution provider

**Branch**: `037-hint-provider` | **Date**: 2026-08-13 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/037-hint-provider/spec.md`

## Summary

Wire the S034-S036 targets hint database into the S027 resolution cascade as the
concrete precedence-2 provider, the final wiring step of issue #78. A new
`HintDatabaseProvider` in `fragcap-targets` implements `fragcap-profile`'s
`TargetProvider` trait: given a Steam appid carried on the resolution request, it
opens a store, looks up the row, and answers with a heuristic-unverified `Target`
built from the row's launch executable (carrying the `launcher_mediated` and
engine facts), or declines honestly when the row is absent, sparse, or ambiguous.
The no-answer stub is removed from `fragcap-profile`, the appid becomes a request
input, a `HintDatabase` target origin and a hint ambiguity note are added, and the
CLI injects the provider only when the `targets` feature is built in and the
operator supplied a database path -- otherwise precedence 2 stays empty and
behavior is byte-identical to today.

The technical approach and every routine decision are recorded in
[research.md](research.md); the shapes in [data-model.md](data-model.md); the
observable behavior in [contracts/hint-provider.md](contracts/hint-provider.md).

## Technical Context

**Language/Version**: Rust, workspace MSRV 1.82 (pinned toolchain for the full gate).

**Primary Dependencies**: None added. `rusqlite` (already in `fragcap-targets`,
S034), `serde_json` (already present). `fragcap-profile` gains no dependency.

**Storage**: The embedded SQLite targets store (S034), read-only here.

**Testing**: `cargo test --workspace --locked`; unit tests over
`Store::open_in_memory()`; cascade-ordering tests via `TargetResolver`.

**Target Platform**: Windows for capture; the store read and the resolution logic
are platform-neutral and the tests run on any host.

**Project Type**: Rust library workspace plus CLI.

**Performance Goals**: N/A (a single indexed row lookup at resolution time, off
the packet path).

**Constraints**: Offline-testable end to end; no network, no game, no capture
driver, no elevation. No new dependency. Dependency direction preserved.

**Scale/Scope**: One provider, one store method, one request input, one target
origin, one diagnostic note, the stub removal, and the CLI wiring. Tier 2 seeding
is out of scope.

## Constitution Check

*GATE: evaluated before Phase 0 and re-checked after Phase 1 design.*

- **P-1 Passive Observation Only (NON-NEGOTIABLE)**: PASS. The provider reads only
  the embedded database. No process handle, no memory read, no launch, no
  transmit. Nothing on the denylist is used or approached. `cargo xtask lint`
  continues to assert the absence of the banned calls.
- **P-2 Core Stays Platform-Neutral**: PASS. `fragcap-core` is untouched.
  `fragcap-profile` gains no platform dependency (the new types are plain Rust).
  The store read stays in `fragcap-targets`.
- **P-3 Capture And Attribution Stay Separate**: PASS. No packet source and no
  attributor is touched. The provider is a resolution-time source of a target
  identity, not a capture or attribution path.
- **P-4 No Silent Loss**: PASS. Every decline is honest: an absent/sparse row is a
  no-answer that lets a lower provider answer; an ambiguous row records a
  `HintAmbiguity` note surfaced through `Unresolved`; a post-open read fault maps
  to a hard `ProviderError` rather than a silent decline; a missing database is
  explicitly not an error, while a present-but-unopenable one fails loudly at the
  CLI boundary.
- **P-5 Compatibility Outranks Richness**: PASS. No output format changes; the
  pcapng and JSON Lines writers are untouched.
- **P-6 Glossary First**: PLANNED. A "Hint provider" term (and the honest-answer
  wording) is added to `docs/glossary/process-and-attribution.md` in the same
  change, alongside the existing "Hint database", "Engine rule", and "Platform
  walker" entries. The index is regenerated by the docs linter.
- **P-7 Wrappers Stay Thin**: N/A. No shell wrapper is involved; the CLI option is
  a thin flag over a Rust capability.
- **P-8 House Standards Apply**: PLANNED. UTF-8 without BOM, LF endings, no
  em-dashes or en-dashes in any new source or docs. `cargo fmt` and the doc linter
  enforce it.
- **P-9 The Instrument Does Not Lie (NON-NEGOTIABLE)**: PASS. Every hint answer is
  `FidelityTier::HeuristicUnverified` with `hint-db` provenance, never authored,
  verified, or observed, and never names a source it did not read. It carries no
  `image_path` because the store does not know one. A live observation still
  overrides a hint at capture time.

**Dependency-direction gate**: PASS by construction. The concrete provider lives
in `fragcap-targets`, which already has the allowed
`fragcap-targets -> fragcap-profile` edge; no reverse edge is introduced.
`cargo xtask deps` is the standing check.

No gate is violated; no Complexity Tracking entry is required.
