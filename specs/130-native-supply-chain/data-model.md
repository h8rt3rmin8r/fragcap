# Data Model: Native Supply-Chain and Compatibility Gate

## SupplyChainPolicy

- `schema_version`: Exact supported policy schema.
- `release_root`: Exact workspace package distributed as the executable.
- `release_target`: Exact target triple for shipped dependency evidence.
- `release_features`: Sorted explicit shipped feature set.
- `workspace_msrv`: Exact supported minimum Rust version.
- `graph_views`: Expected digest, package count, and edge count for Windows all-feature, Linux all-feature, and shipped Windows closure.
- `allowed_sources`: Closed registry and workspace-source rules.
- `critical_dependencies`: Sorted maintenance records for security-sensitive direct packages and tool inputs.
- `duplicate_compatibility_exceptions`: Finite records for approved simultaneous compatibility lines.
- `unsafe_reviews`: Reviewed security-critical or platform package families bound to one complete graph digest.
- `exceptions`: Finite rule-specific exceptions; empty is valid.

## NormalizedGraph

- `view`: Closed graph-view identifier.
- `root`: Workspace root package or complete workspace.
- `target`: Exact target triple.
- `feature_mode`: All features or explicit sorted feature list.
- `packages`: Sorted normalized package records.
- `edges`: Sorted normalized dependency edges.
- `digest`: SHA-256 over canonical package and edge records.
- `complete`: True only after all resolved nodes and edges reconcile.

## PackageRecord

- `identity`: Stable name, version, and source tuple.
- `checksum`: Registry checksum when applicable.
- `workspace_path`: Repository-relative identity for workspace members; never an absolute path.
- `license`: Declared SPDX expression or explicit missing state.
- `rust_version`: Declared Rust floor or explicit missing state.
- `features`: Sorted activated features.
- `roles`: Runtime, build, development, or combinations.
- `targets`: Sorted target expressions through which the package is reachable.

## DependencyEdge

- `from`: Stable package identity.
- `to`: Stable package identity.
- `kind`: Normal, build, or development.
- `target`: Exact target expression or unconditional marker.
- `declared_name`: Dependency name used by the parent.

## CriticalDependencyRecord

- `package`: Exact package or tool identity.
- `requirement`: Exact version or strict constraint.
- `features`: Sorted expected features where applicable.
- `default_features`: Expected default-feature state.
- `owner`: Maintainer identity.
- `cadence_days`: Maximum review interval.
- `last_reviewed`: ISO date.
- `compatibility_boundary`: Required platform, protocol, crypto-provider, MSRV, or output checks.
- `emergency_expectation`: Required response class for an actionable advisory.

## PolicyException

- `id`: Unique stable identifier.
- `rule`: Exact closed rule identifier.
- `package`: Exact name and version scope; wildcards prohibited.
- `tool`: Exact governed tool when the finding belongs to a release-tool graph.
- `tool_version`: Exact governed tool version when the finding belongs to a release-tool graph.
- `owner`: Responsible maintainer.
- `rationale`: Specific reason the policy cannot yet be met.
- `created`: ISO date.
- `expires`: ISO date after creation.
- `removal_condition`: Observable condition that ends the exception.
- `used`: Derived only; an unused exception fails.

## SupplyChainReport

- `schema_version`: Exact report schema.
- `policy_digest`: SHA-256 of policy bytes.
- `graph_results`: One result per required view.
- `findings`: Bounded sorted rule violations.
- `exceptions_used`: Exact exception identities matched to findings.
- `complete`: True only when all graph views and policy sections reconcile.

## ReleaseEvidenceIdentity

- `fragcap_version`: Workspace version.
- `source_revision`: Tagged commit.
- `source_date_epoch`: Tagged commit time.
- `target`: Release target.
- `features`: Exact release feature set.
- `lock_digest`: SHA-256 of `Cargo.lock`.
- `policy_digest`: SHA-256 of policy bytes.
- `generator`: Exact tool and version.

## SoftwareBillOfMaterials

- CycloneDX JSON 1.5 generated by cargo-cyclonedx.
- Root application component is `fragcap-cli` at the release version.
- Components and dependencies reconcile exactly to the shipped runtime closure.
- Component identities never contain absolute workspace paths.
- Metadata properties carry the release evidence identity.

## ThirdPartyNotices

- Deterministic text generated by cargo-about from the exact release manifest and target.
- One unique package marker per external shipped component.
- Each section carries package identity, version, source or repository, SPDX expression, and resolved legal text.
- Workspace packages and development-only packages are excluded.

## State Transitions

```text
metadata unavailable -> could not run
metadata resolved -> normalized
normalized + policy mismatch -> failed
normalized + policy match -> static approved
static approved + fresh cargo-deny pass -> ecosystem approved
ecosystem approved + evidence generated -> evidence pending validation
evidence reconciled -> package input approved
package input approved + existing release authorization -> eligible for packaging
```
