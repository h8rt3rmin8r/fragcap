# Research: S171

## Retention selection

Decision: new managed output declares 30 days, 20 completed sessions and 2 GiB; explicit saved/custom output and historical retain-until-explicit-cleanup output remain retained. Rationale: finite history resolves #458 without retroactively contradicting evidence promises. Alternatives: silent migration deletes historically promised evidence; only explicit cleanup leaves ordinary accumulation indefinite.

## Eligibility and deletion

Decision: strict terminal manifest plus exact closed journal, all latest external obligations settled, complete recognized population and inactive owner generation. Rationale: a terminal row or artifact presence cannot prove whole-session safety. S170 access_repair checks exact trailer identity/count and recognized sidecars; its no-delete permission pins must not be used for deletion. Alternatives: path deletion after canonicalization permits replacement races; broad recursive removal includes unknown data.

A failed or timed-out artifact producer is collectible when terminal authority proves that writing has ended and every external routing/trust obligation is settled. Failed evidence production is distinct from an unresolved external effect; pending sensitive actions and retained external resources remain refusals.

Decision: DELETE-capable exact handles and synchronized external retirement state precede removal; preserved root and outer ancestors remain guarded. Rationale: retries after manifest removal need independent authority and replacements must survive. Logical removed bytes are counted only after successful close/absence. Primary API references: [SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle), [FILE_DISPOSITION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_disposition_info).

## Shared session and Doctor integration

Decision: LibraryArtifactAdapter.prepare is the shared allocation/ownership boundary; run_with_outcome after session consumption is the maintenance boundary, excluding just-returned output. Rationale: Capture and guided calibration share the same authority; plan-only and read-only commands stay read-only. Explicit guided attempt subdirectories inherit custom retention from allocation intent.

Decision: stream root containers and separate healthy/empty counts from actionable finding capacity; show scan limits. Rationale: current 200-entry recursive budget counts every historical file/container and a malformed owner can abort all owner parsing. Alternatives: summarizing healthy rows only does not fix inventory starvation; unbounded vectors trade the defect for memory growth.

Decision: new generation and maintenance mutexes use the Windows Global namespace. Historical Local leases remain active when observed; an absent Local lease plus an extant/reused producer PID remains unresolved, while a permitted process snapshot proving producer absence corroborates ended ownership. Rationale: Local namespaces differ between desktop sessions, so absence alone cannot authorize cross-session deletion. [Microsoft kernel object namespaces](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces) distinguishes global mutex visibility from privilege requirements for global mappings and symbolic links. No process handle or new dependency is introduced.
