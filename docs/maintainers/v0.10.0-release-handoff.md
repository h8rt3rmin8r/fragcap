# v0.10.0 release handoff

S150 prepares a minor release for the stable version-one Rust API, guided target registration/setup and resumable calibration, current native documentation, session/help UX, and accumulated dependency maintenance since v0.9.0. It does not publish, tag, run the installed sensitive product, claim universal compatibility, or complete independent review. The [short notes](../../release-notes/v0.10.0.md) summarize user-visible changes separately from the assembled changelog.

## Preparation boundary

The existing `release.toml` permits local version-only Cargo release operations on `release/*`. S150 therefore uses `release/0.10.0`, overriding the usual `codex/` feature prefix solely for that established policy. Spec-kit artifacts remain at `specs/150-native-review-release`. The main-only `New-Release.ps1` orchestration is not run from this in-progress branch, and its native child launches are not used on the desktop. Instead, configured Cargo release, exact embedded/portable identity updates, existing golden generators and changelog assembly run through verified hidden, redirected launchers with targeted staging. No release policy, package budget, crypto provider, publication workflow, or historical physical measurement is weakened.

## Operator merge and publish

Merge only after current-head CI and PR review are satisfied. Confirm merged main contains the prepared version, changelog, notes and acceptance evidence. The operator creates and pushes `v0.10.0` at that exact revision. Tag CI builds once, certifies final packages, transfers and rehashes those exact bytes, and creates the GitHub release. Registry publication remains behind the existing `crates-io` environment approval after release creation. No tag or registry action is authorized to the implementation agent in this slice.

Do not publish around failed certification, reconstruct downloads from a different build, move a failed tag, or treat unsigned downloads as signed. Keep the release run and certification report as authority. Follow [package certification](package-certification.md) and the existing contributor release workflow. If publication fails, repair through a PR and cut a fresh semantic version rather than silently retargeting immutable evidence.

## Validation after published bytes exist

The operator installs or unpacks the newly published digest-verified package, performs the desired bounded validation, and supplies sanitized actual results. Reproduction of elevated Doctor stall #372 is specifically pending on these bytes; no guessed fix or invented readiness is included. Independent reviewer(s) use the [twelve-area handoff](../security/native-product-review-handoff.md), freeze actual tag/lockfile/package/build identities, and perform authorized installed-build review separately from implementation authors.

Issue #411 is bounded preparation delivery. Documentation #331, independent review #333, and completion #334/#278 remain open until their actual acceptance is satisfied. Optional operator live-title testing is not an agent-run definition-of-done gate, and lack of that test is never represented as approval.
