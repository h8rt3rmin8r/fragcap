# Contract: Installed Route, Correlation, and Report Acceptance

## Selected route

One controlled package case declares package surface, IP family, the required native route stream, exact cold client, external peer, unrelated sentinels, expected bytes, and expected cleanup. The signed-driver library runs separate diagnostics-on and diagnostics-off cases. A passing case requires the client and peer to agree on nonzero byte counts in both directions, no missing sentinel reply, no unexplained post-receive loss, and no residual route or remote listener. SOCKS CONNECT alone is insufficient.

## Passive packet order

For each physical order, record the exact original tuple and selected receipt, Npcap capture start and stop, original-packet presence, later packet availability, process generation, client response, proxy transfer, compatibility outcome, stored fact, and ordinary admission. Original-present and original-absent positive cases must agree on route reachability while retaining distinct packet statuses. A synthetic fixture has a separate evidence tier.

## Native debug report

The report accepts complete and partial native bundles, reads bounded versioned sources, and returns explicit source status for route, process, proxy, packet, compatibility, manifest, and cleanup. It never writes to the source bundle. A malformed or missing input cannot become complete. The shareable projection uses opaque flow labels and declares omissions; private route receipts and unrelated payload do not leave their source authority.
