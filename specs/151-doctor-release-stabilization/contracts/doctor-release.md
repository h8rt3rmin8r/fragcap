# S151 Doctor and Release Contracts

## Doctor Surface

Visible `fragcap doctor --timings` changes only eligible interactive normal human read-only completion diagnostics. By default, completions lasting at least one second include milliseconds automatically. Pending output is `doctor: still checking <fixed phase> after <elapsed> ms (waiting for this operation to finish)` after one second and no faster than once per second. Readiness leaf names identify actual aggregate call boundaries; tracing includes existing availability and owned teardown without specific historical API attribution.

Progress is stderr only. JSON, redirected human, quiet, silent and fix paths emit none. Final report bytes/schemas, classifier facts, checks, readiness and exits stay unchanged. Diagnostic write failures are best effort. Work panic never becomes success. One worker is explicitly joined; no timeout, independently surviving work or cancellation guarantee is introduced.

## Publication Surface

`docs/published-release.json` records reviewed publication, not current source features. Every enumerated current surface contains exactly one standalone `Published baseline: [v<version>](<official URL>).` paragraph. Currency checks validate identity/markers and reject contradictory current-baseline claims. Historical preparation and release history can retain older versions. Current CLI guidance separately states S151 diagnostics are unreleased and published v0.10.0 retains hidden completion-only timings.

Actual baseline remains v0.10.0 / `787739edfa8d748e25cb4b5c4965f5c936850d16` / 2026-09-15; a newer candidate workspace version must not change that fact. No signing, independent approval or final completion claim, registry setting mutation or immutable release change is made.
