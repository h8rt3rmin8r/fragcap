# S170 access contract

## Library interfaces

The additive facade recipient object retains a validated ordinary context and exposes exact SID/proof description, directory protection, private-child protection and actual recipient-context verification. Existing prepare_bundle/open_sensitive_file signatures remain supported for explicit current-account library callers. A new prepare_bundle_for_recipient operation establishes an exact selected context for the session, and all independent writers inherit/preserve its private contract. No process-global mutable recipient is introduced.

Facade inspection binds a recipient to an exact recognized bundle and pinned complete population. Repair accepts the current inspection plus exact authorization identifier and returns external per-path effects and recipient verification. Windows handle operations are shared through the access adapter, and platform-neutral core has no token or ACL dependencies.

## CLI interfaces

`deep-capture` and `calibrate` accept `--output-recipient <SID>` only with an explicit `--bundle`. Default production desktop identity is validated against the exact token session account. Different-account selection emits an exact finite local request and an ordinary-session helper command. `bundle access-authorize --request <REQUEST> --bundle <PATH>` connects as the intended ordinary account, confirms exact destination binding and submits one authenticated handoff. Structured events never contain token handles, passwords or captured payload.

`bundle access-inspect <BUNDLE>` performs bounded read-only inspection. `bundle access-repair <BUNDLE> --authorize <INSPECTION_ID>` recomputes the exact current proposal before permission changes. Both support explicit recipient selection through the same validated workflow. Human output preserves exact values and four-space measured column anchors at narrow and wide widths. Structured output identifies schema/version, recipient, population, reasons, inspection id and actual per-path outcomes.

No bare blanket confirmation authorizes a different preview, and ordinary Doctor remains read-only. Missing/unreadable provenance, active/unknown ownership, unknown paths, stale identity, reparses and unproven external hard links refuse repair before mutation. Inspection reports unavailable access rather than inventing current grants.

The inspection includes every necessary proven fragcap-owned parent container above the bundle, up to eight, with pinned identity, existing descriptor and proposed non-propagating traversal/enumeration-only recipient grant. CLI supplies exact container authority. Parent changes must not propagate into sibling bundles; arbitrary profile/custom ancestors are inspected for access but never mutated. An inaccessible unowned ancestor leaves repair unresolved. Parent results and partial failures are included in the same actual-effects report and digest as artifact paths.

## Session publication

The complete session plan binds exact output recipient and destination alongside existing target, trust, route and deadline authority. Recipient proof is revalidated after approval. Protection precedes resource writers and session external effects. Verification after final reconciliation covers all existing retained files, including sidecars and atomic replacements. `written` never implies recipient-access verified. Failed verification is a required artifact/access failure and withholds accessible analyzer-open guidance.

## Preserved authority

Permission repair leaves bytes, artifact names, retention decisions, resource obligations, proxy/trust state and empty containers intact. Producer-private ephemeral DPAPI authority material remains producer-private; retained evidence receives the recipient contract. No release or live-game compatibility claim follows controlled access verification.
