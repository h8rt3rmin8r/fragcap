# Data Model: Reviewable Release Handoff

## Documentation corpus

Current README plus authored non-historical site documentation contains parser-checked fenced `fragcap` invocations. Historical changelog, generated glossary, and measured spike reports remain outside current-command promises. New authored pages enter the check automatically; malformed quotes and invalid options fail without dispatch.

## Review scope registry

A closed versioned registry contains twelve unique canonical areas, each with repository source paths, exact executable test references, explicit package-feature arrays, and a named validation method. Git tracking, Cargo target ownership, and compiled test-harness discovery with defaults disabled protect against generated specimens and enclosing configuration that removes a test. Missing, duplicate, unknown, ignored, or stale references fail. Registry validity means reproducibility readiness, not independence or successful test execution.

## Independent review record template

The committed template is explicitly `not-started`. Source SHA, final product version confirmation, lockfile digest, package checksum rows, reviewer independence, environment, executed checks, findings, and closure are filled privately by the authorized reviewer after actual publication. Empty findings mean no audit has occurred. Findings retain severity, ownership, reproduction, affected identity, disposition, independent retest, and explicit operator acceptance separately. Public summaries disclose methods and closure, not raw sensitive evidence.

## Release state

v0.9.0 remains the last published baseline until operator tagging and successful publication. v0.10.0 is a prepared candidate. Historical physical evidence keeps its measured identity; portable version-bound evidence is rerun, not relabeled as physical proof. Exact calibration rows remain append-only and require fresh applicability under the new product version.
